## Deployment boundary

Current `ci.yml` publishes an immutable `cms-dev-<full SHA>` development prerelease only after quality, coverage, complete isolated application verification and actual native selfhost compatibility pass on main. The existing authorised development controller polls roughly every five minutes, requires the exact current-main successful CI/release identity and validates archive hashes, migration history and public configuration before installation.

Therefore an eligible feature merge may update the authorised development VPS at `https://cms.luminovia.org`. This is within the new prompt's development release scope, and does not authorise production, public DNS, marketing Website deployment, plan upgrades or real email. Source implementation or a GitHub merge is not proof of actual VPS installation. Additive migrations still must pass its reviewed-history/data-mutation guard; never weaken that guard to force installation. Existing accepted financial records and populated databases are preserved.

The active workflow inventory at this checkpoint contains Portal checks, Daily verified component maintenance, Pull request metadata, Security analysis and Dependabot Updates. Proposed #19 auto-merge and #18 preview publishing must not be assumed to run from current main.
