## Concrete findings and disposition

1. **P2 — direct account RPC could bypass its pagination cap with NULL.** The original `account_users` predicate checked `NOT BETWEEN` without rejecting null limits/offsets. A disposable real PostgreSQL reproduction with 102 fictional users returned 100 items for `p_limit=100` and **102** for `p_limit=NULL`; the latter became `LIMIT NULL`. The HTTP query validator did not protect callers using the public RPC directly. The account owner added explicit null checks and regressions in `accounts-db-tests.mjs`. Current source contains those checks. The reproduction used a temporary database only.
2. **P3 — duplicate profile time-zone validation.** The new migration originally added `profile_time_zone_guard`, while the foundation already had `profiles_time_zone` invoking the same IANA validation on the same events. This duplicated business validation and changed the error depending on trigger order. The owner removed the new trigger/helper and kept the original authoritative guard. Current source confirms removal; direct-REST regression now checks the native validation error code.
3. **P2 — converted draft offers inflated published financial counts.** Commissioned draft creation converted the request internally but kept the actual job draft. The request reader mapped it back to submitted, while spending counted the internal request's published marker. Fixed under coordinated ownership: the report now uses actual linked job status and counts only published/filled jobs. The real SQL regression creates a draft, asserts one request and zero published/assigned offers, then publishes it and asserts exactly one published offer. All 14 commission SQL checks passed after this change.
4. **P3 — client-organisation HTTP route missing from the initial OpenAPI paths.** The handler implemented PUT/DELETE `/v1/users/{id}/organisations/{organisationId}`, but the initial OpenAPI document did not list it. The root owner added both operations to `accounts/openapi.ts` and their handler/API tests passed. This was contract-documentation coverage, not an observed authorization bypass; both operations call the same MFA-protected `manage_client_organisation` RPC.

**P3 — canonical function lint caught an implicit JSONB initializer cast.** An earlier canonical run stopped at a warning in `create_client_request` for `sessions jsonb := '[]'`. The declaration now uses `'[]'::jsonb`. All non-trigger application PL/pgSQL functions returned an empty `plpgsql_check_function_tb` issue array in a disposable replay, and canonical run 03 passed the actual complete schema lint/advisors.

No other concrete unauthorized gross read, private-DM/calendar bypass or parallel invitation ledger was identified in these reviewed paths. That limited observation does not establish an absence of vulnerabilities elsewhere.
