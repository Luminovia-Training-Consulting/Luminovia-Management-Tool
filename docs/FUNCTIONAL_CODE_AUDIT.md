# Functional and code-connection audit

Audit date: 16 November 2026 (Australia/Brisbane). This review starts from merged M3 (`00db7c9`) and checks the M4 worktree as new features are integrated. It records inspected code and executed checks; it is not a certification that every possible input, platform or production configuration is defect-free.

## Repeatable checks

```bash
node scripts/code-integrity.mjs --exports
node --test scripts/runtime-code-integrity.test.mjs
./portal test
```

The first command prints a machine-readable source inventory. It follows ordinary, type-only and literal lazy imports from `src/main.tsx`; checks relative imports, literal internal links against the real nested React Router routes and literal public image assets; and reports exported runtime declarations with actual compiler-symbol references. Import/export declarations and tests alone do not count as production uses. The guarded source has no waiver list of unused frontend modules or completely unreferenced runtime exports.

The six code-integrity cases are automatically discovered by `./portal test` alongside the existing runtime safeguards. A temporary synthetic source tree proves that an orphan module, unused export, absent lazy import and unregistered route are detected. Another fixture proves that renamed imports, generic RPC wrappers, transitive wrappers and endpoint parameters in different positions are followed, while comments/authored string lookalikes are ignored.

`scripts/api-surface-db-tests.mjs` now uses the same compiler-based RPC scanner. It discovers wrappers from how they forward their parameters to `.rpc`, instead of maintaining a special-case list such as `peopleRpc`. New comment, building-block or avatar helpers are therefore included automatically. The test compares each delivered literal call with the actually replayed PostgreSQL function/grant inventory and checks public invoker boundaries and exposed-table RLS. Its successful replay belongs to the canonical result in QA_RESULTS; a static name match alone does not prove permissions or transaction behaviour.

## Export and entry-point decisions

At the initial symbol pass, 149 exported runtime declarations had real production references; none was a completely disconnected helper. Later M4 declarations are included by the repeatable command, rather than relying on that earlier count.

- `TextLink` is live in the dashboard's jobs, calendar and role-specific shortcut. It was inspected and retained.
- `MessageText`, `csvCell`/`csvText` and avatar `sourceImageSize` are used inside their production modules and directly imported by focused text/link, formula-safe CSV and image-boundary tests. Those small exports preserve explicit safety-contract tests; they are not unused production code.
- Public PostgreSQL functions, private implementations, migration history, Supabase Edge entry points, runtime scripts and test discovery entry points are separate application interfaces. A function without a direct browser call is not automatically dead. Do not delete a headless API or old migration because a frontend text search finds no reference.
- The module guard follows literal imports. A future computed import registry or generated entry point requires an explicit inspected design and corresponding guard support. Type references establish a connection, not a guarantee that a particular runtime branch executes.

## Executed scope and limits

The dedicated source run passed **15 cases across three files**: Auth flows, MFA and portal-search navigation. Targeted ESLint and formatting passed for the changed audit/Auth/search code. The final source-integrity run passed **all six cases**: **84 frontend modules, 25 registered routes and 172 exported runtime declarations** had no unreachable module, missing relative import/image, unregistered literal link or unreferenced runtime export. During construction the guard identified two building-block symbols awaiting integration; root subsequently wired the actual job-defaults query and building-block reference. They were not deleted or hidden by a waiver.

The full canonical result, actual new feature APIs, migrated function count and final desktop/mobile screenshots belong in [QA_RESULTS](QA_RESULTS.md) and [WORKLOG](WORKLOG.md). This report does not substitute mocked Auth failures for actual Auth/TOTP success, static graph scans for authorization tests, or Chromium emulation for physical mobile installation/manual accessibility. Hosted SMTP/security/privacy, retention/restore and the remaining full master-prompt modules are separate acceptance gates. No normal development, hosted data, real recipient or payment was changed by this audit.
