# LMS packages and installation rights

This matrix records the package boundaries and their enforcement in the current
portal and Academy workflows. Academy means either managed or self-hosted White Label. Its signed
installation licence still controls availability. Active permits authorised
writes, grace permits the existing approved reads, and expiry denies access.
Individual package changes do not amend signed licence terms.

| Function | Package | Portal and Academy navigation | API and current gate | Authority and data |
| --- | --- | --- | --- | --- |
| Course templates, drafts, publication and archiving | Standard | Courses, calendar, templates, enquiries and reuse | `course_creator_drafts` and `course_creator_draft_action` in both editions. Portal uses `save_course_run` and `set_course_visibility`. Academy uses `academy_save_draft_schedule` and `academy_publish_course`. | Company or course manager scope. Preserve origin, revision and date/time zone. Offer preparation and publication are separate. |
| Series and schedule | Standard in both editions | Courses → Series and saved course detail → Edit series pattern | `course_series_classes`, `plan_course_series`, `course_series_for_run`, `revise_course_series` | Course managers and internal company authors of their own series. Academy active for editing and grace for reads. Scoped preview and confirmation preserve untouched runs and reject stale saves. |
| Reviewed course archive and restore | Standard in both editions | Courses list or Academy Learning → Manage course archive | Shared `archive_course_runs` command. Academy uses `academy_course_archive_runs` to list current and archived courses. Active licence required to write. Grace permits list reads. | Current course managers review 2–50 runs. Academy scope is active organisations in the installation. Stale states and locked courses reject the whole batch. Publication and assignments are preserved. |
| Course timeline | Standard in both editions | Course detail or workspace → Course timeline | `course_timeline` reads up to 100 milestones. Academy allows reads while active or in grace. | Current course staff see event IDs, categories and times for the exact course. Linked instructor events require assignment management authority. |

| Curriculum | Standard | Learning → Course → Curriculum | `course_content_studio`, `course_content_action` and publication queue. Standard authoring and playback. | Attendance and basic progress | Standard | Course register and learning workspace | `save_course_session_attendance`, attendance import, redacted single-session export and scoped learner workspace | Current register authority, verified attendance separate from self-report. | Programme structure and progress | Standard | Learning → Programmes | `learning_programs`, `configure_learning_program_curriculum`, `start_learning_program_course` | Same-company course and membership only. Preserve required/elective rules, sequence, exceptions and progress. |

Keep immutable versions and protect answers and marks. |

| Competencies, portfolio and formal receipts | Premium | Course results, portfolio, receipt download | `course_competencies`, `course_competency_action`, `learning_portfolio`, `learning_portfolio_command`, `course_completion_status` and `completion_issue` through the edition’s workspace action RPC | Retain scoped evidence and revocation history. ## Routes by installation

| Area | Luminovia portal | White Label Academy |
| --- | --- | --- |
| Course planning | `/courses` with the calendar at `/calendar`, templates in `/courses?tab=templates` and reviewed enquiries at `/enquiries`. Saved copies and series can open `/courses?editRun=<id>`. | `/learning` contains authorised draft creation and the shared series form. `/courses` redirects to the Academy course hub. |
| Company and learner access | Company participants at `/clients` or `/admin/clients`. Accounts at `/admin/accounts`. Course assignments, withdrawal and attendance use the authorised workspace at `/courses/<id>/workspace`. | Academy account roles and participant management apply to the current installation. Authorised staff manage the course roster and attendance at `/courses/<id>/workspace`. |
| Content, materials and programmes | `/courses/<id>/workspace`, `/learning?view=materials` and `/learning?view=programmes`. Standards-based packages use the same workspace as the ordinary files and curriculum. | The same workspace and learning routes use the signed installation's existing access gate. |
| Assessment and evidence | The workspace exposes authorised Premium assessments, results and evidence. Personal evidence views use their own role and ownership checks. | The same learning routes expose the licensed Academy views. Grace and expiry continue to be decided by the installation licence. |

The approved White Label setup selects the Academy's LMS package separately from the managed or self-hosted installation. The Academy's signed edition and release still control installation access. An approved `lms-standard` licence enables the shared Standard workflows. An existing `lms` licence continues to include the full previously licensed scope, including Premium. Version 2 licence requests can select `lms_package` as `standard` or `premium`. Renewal of a Standard licence requires an explicit package. Package changes apply only after installing the newly signed terms. Grace keeps approved reads available and expiry closes the course profile. A downgrade retains published versions, assessment records and issued receipts in their existing scope.

The current implementation moves the internal participant invitation, class
placement, enrolment, attendance register, ordinary course materials, curriculum and programme operations
to Standard. The material picker lists eligible clean versions for course managers.
Ordinary material metadata and reuse are available in Standard with the existing file ownership and scope checks. Changing competency links still requires Premium. Standard programme progress can use a completed enrolment
where there is no formal receipt history. If a receipt exists, its revocation
still withdraws the corresponding credit.

The series creation form accepts a per-run teaching-day count and daily
start/end override in the shared time zone. Saved patterns can be edited for selected eligible future drafts after a new preview. Legacy schedules keep their exact dates until a rule is entered and confirmed. Course detail combines visible sessions with
the recorded creation and archive dates. Current staff also see committed series changes, publication and class events in the same timeline in the internal portal and Academy via `course_timeline`. Recorded archive and restore transitions remain visible after restoration. Managers with assignment authority see confirmation and release on the exact linked course. The timeline provides only the event category and time. The same archive and restore transaction serves the internal course list and the Academy archive. A reviewed copy opens the saved draft in the portal course editor. Saved series link to the relevant run and its shared pattern editor.
