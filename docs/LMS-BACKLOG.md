# LMS delivery backlog

This ledger tracks the educational-only LMS extension from the implementation directive. It extends the existing Luminovia course run, enrolment, assessment, document, attendance, certificate and analytics authorities; it does not create parallel registries. The authoring baseline was `main` at `9d1dbdba`; the catalogue branch starts at `26431400`, now on `main`. This document distinguishes source implementation, local verification, browser verification, external interoperability and production acceptance.

## Coordination and ownership

- Shared course, enrolment, migration and API ownership: LMS maintainers; migrations must preserve the existing `course_runs` and `course_enrolments` authority.
- Work packages are sequential at P0, then P1, then P2. Do not parallelise changes to shared grade calculations, enrolment versions or completion decisions without an assigned owner and agreed migration/API boundary.
- No AI functionality, privileged executable lesson HTML, production deployment, external provider activation or destructive migration is in scope.
- The first authoring implementation is in `0ef0eb77`; autosave verification is in `c51efa32`. The copy, move and narrow-preview follow-up is on the same branch, `codex/lms-p0-course-authoring`.

### LMS-P0-03 — gradebook and configurable grading policies

- **Priority / status:** P0 · the DE/EN course workspace provides a quiz gradebook and weighted course grades. Weighting uses existing course enrolments and released quiz, exam, text exam and assignment results.
- **Data and security:** Private RLS-enabled tables retain immutable policy and grade revisions. The preview uses the highest score on the current published quiz. Ties prefer the latest attempt, then the lowest attempt ID. A policy displays percentage or the label for the highest threshold reached. Release checks the reviewed attempt and policy. Corrections and recalculated releases require the current grade revision and a reason. Current learners can read only their own released history. Internal reasons and the current-grade CSV export are scoped to course staff. Academy grace allows reads and exports.
- **Affected modules:** `course-gradebook.tsx`, `course_gradebook`, `course_gradebook_history`, `course_gradebook_export`, and the `gradebook_*` commands in `course_workspace_action` and `academy_learning_action`.
- **Acceptance and tests:** Focused component cases cover versioned release, offline state, conflict recovery, grace, reasoned recalculation and paginated history. The PostgreSQL cases exercise API grants, competing writes, privacy, current membership and both Academy licences. Desktop/mobile functional tests exercise release, correction, recalculation, history and CSV. See [readiness evidence](PRODUCTION-READINESS.md#verification-record-for-lms-p0-03) for the commands that passed.
- **Weighted grades:** Versioned policies define weights, required and optional results, the missing-result policy, individual exemptions, capped bonus, and a separate pass threshold. Staff review an exact evidence snapshot and can require a second reviewer for publication. Learners see their own immutable release history. Individual and team assignments use the latest applicable released assessment. PostgreSQL and real desktop/mobile Chromium verified the weighted release path and the separate quiz-gradebook path.
- **Notifications and remaining work:** Released weighted grades and text exam assessments create a current-learner inbox entry with the course link. Hierarchical categories, programme reporting and reviewed spreadsheet imports remain open.

### LMS-P0-04 — reusable question bank and examination builder

- **Priority / status:** P0 · partially implemented. Course staff can create, search, revise, archive and restore reusable objective questions by organisation, topic and difficulty. The quiz builder can mix manual entries with exact bank revisions. A fixed quiz can shuffle its order once per revision. A quiz made entirely from exact bank revisions can instead draw a smaller random subset when a learner starts an attempt.
- **Data and security:** Append-only question history and per-quiz provenance preserve the accepted question and options across edits. Current course staff can read their organisation's bank; authors and course managers can change items. Learners receive the prompts and options of their current published quiz or own persisted draw. Pool candidates and answer keys are staff-only. The canonical attempt, scoring, certificate and gradebook sources continue to consume the existing quiz versions and attempt records. In dedicated Academy editions the bank can be read during grace, with an active licence required to write.
- **Verification and remaining work:** Local PostgreSQL covers scope, append-only revisions, conflicting edits, snapshot integrity, archiving, restore and scoring with an idempotent attempt. A focused desktop and mobile Chromium journey exercised bank creation, quiz publication, a later bank revision, learner draft recovery and a submission against isolated Auth and PostgREST. Current learners can resume their own server-confirmed answers without consuming an attempt. Saving an accepted attempt removes its draft. Pool-specific PostgreSQL and desktop/mobile Chromium checks cover private draw creation, exact recovery after reload, authoritative scoring and a subsequent draw. Native timed text exams support versioned papers, private resumable answers, per-question manual scoring and explicit release of versioned feedback and grades. Rubric moderation and exam exports remain open. External standards import and proctoring require their own product scope.

## Verification vocabulary

- **Planned:** no integrated source implementation.
- **Partially implemented in source:** functionality exists but its package acceptance criteria are incomplete.
- **Locally verified:** actual named local command/test passed.
- **CI verified:** reviewed canonical CI for the relevant commit passed.
- **External integration verified:** named, authorised external sandbox or provider acceptance passed.
- **Production accepted:** separately authorised production rollout and monitoring evidence exists.

Source presence, a passing focused local test, a browser mock, or a migration replay does not imply later categories.
