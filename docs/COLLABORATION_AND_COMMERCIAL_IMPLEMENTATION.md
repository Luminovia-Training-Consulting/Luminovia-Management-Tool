# Collaboration, knowledge and commercial frontend

This document records the implemented source interfaces and the evidence available before the next isolated full-stack test. It complements [ROADMAP](../ROADMAP.md); it does not narrow the Universal Master Prompt.

## Implemented interfaces

- `/chats`: scoped contact directory, idempotent direct messages, staff groups and explicit course participant groups, general lecturer room, cursor-paginated and searched messages, unread/read and mute state, safe text links, own edits within the server window, confirmed tombstone deletion, reactions, scanned private attachments and group membership management. PostgreSQL subscriptions wait for actual replication readiness. Own membership tombstones clear the removed room's cached messages and members immediately; subsequent reads and downloads recheck server permission. No private message administrator bypass, broadcast history, simulated presence or optimistic send confirmation.
- `/wiki`: Tiptap JSON editor, literal code blocks with language highlighting, categories, German/English authored-page locale, personal drafts, manager publishing, version history and optimistic version conflict checking. An author's later draft does not replace the published snapshot for other readers.
- `/forum`: categorized discussions, idempotent replies, own edits, tombstone deletion, owner/moderator accepted answers, subscriptions, reports and manager moderation. Locked discussions block ordinary author edits and replies. Participants receive no implicit knowledge access.
- `/contracts`: manager MFA registration of externally executed clean PDF versions, lecturer ownership, effective/expiry instants in the viewer's explicit IANA zone, linked addenda, exact-version download and SHA-256, and lecturer receipt acknowledgement bound to the exact hash. The interface explicitly identifies this as receipt acknowledgement, not an electronic signature. Legacy metadata without a PDF cannot be acknowledged or downloaded.
- `/finance`: server-scoped own/management earnings with separate original EUR and AUD totals, accepted compensation stages, clean PDF invoice submission against up to 50 own claims in one currency, manager review and note, recorded partial/full payments, payment history and audited correction through void records. Amounts come from immutable accepted claim snapshots; the interface is not a tax calculation or bank transfer service. CSV export quotes cells, replaces CR/LF/tab and neutralizes formula prefixes after leading whitespace.

Feature query keys are scoped to the authenticated actor and relevant entity. All writes use real Supabase RPCs or the private files gateway, require connectivity and report success after server confirmation. Stable request UUIDs survive uncertain retries. Message bodies and JSON rich text have no arbitrary HTML rendering path. Server permissions, validation, invoice totals and concurrency constraints remain authoritative.

## Source ownership and integration

Feature source is in `src/features/chat`, `src/features/knowledge` and `src/features/commercial`. Translations register isolated `chat`, `knowledge` and `commercial` namespaces. Entry points are `ChatPage`, `WikiPage`, `ForumPage`, `ContractsPage` and `FinancePage`. Shared files APIs provide quarantine/scanning and fresh-authorized exact-version downloads. Central routing, navigation, backend migrations, runtime and deployment ownership are tracked in the QA results.

Knowledge attachments are pending a dedicated knowledge ACL/storage adapter. The editor does not expose personal-file URLs as an unsafe substitute. Chat currently uses validated PostgreSQL message and membership streams; ephemeral typing/presence is pending a revocation-safe design.

## Test interpretation and remaining acceptance

The wiki browser fixture uses desktop **Enter** and the Android-emulated **Shift+Enter** event path to create code lines. Desktop Shift+Enter exits the code block. The test checks exact multiline text before saving and after persisted rendering, and verifies that authored script syntax remains text. Plain hardware Enter did not create a newline under the emulated Android user agent; no speculative product workaround was added. Native Android virtual-keyboard Enter behavior remains an explicit manual physical-device acceptance item.

All mutation browser tests require `PORTAL_TEST_MODE=1`, loopback Supabase and isolated fixtures. No normal development business records or production data were mutated by this feature verification. Native installation, physical browser/keyboard acceptance, hosted staging/production acceptance, legal/e-signature certification and real bank transfers are outside this evidence.
