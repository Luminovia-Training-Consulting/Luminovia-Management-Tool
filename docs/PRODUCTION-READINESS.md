## Verification record for P0-06 transactional SMTP outcome handling

- The private relay preserves explicit provider `4xx` and `5xx` result classes using fixed, sanitized worker replies: temporary `451` and permanent `550`. SMTP response text is discarded. Rejections during session setup, `MAIL`, `RCPT` or final `DATA` are classified before the worker records its outcome.
- After DATA, a missing response, connection loss or nonstandard final response is marked uncertain and the private SMTP connection is closed rather than issuing a retryable response. A disconnect or incomplete frame before the SMTP DATA terminator cannot submit a message upstream. Socket cleanup exceptions cannot replace a known provider result.
- Passed locally: `python3 -m unittest scripts.test_mail_relay scripts.test_notification_mail_worker` (53 tests), using loopback listeners, fictional recipients and a controlled provider transport. Coverage includes accepted, temporary/permanent rejection at session/envelope/data phases, sanitized replies, no submission for pre-body rejection or incomplete DATA, ambiguous outcomes and cleanup failures.
- The release packaging suite (`node --test deploy/hostinger/updates/package.test.mjs`) passed all 33 tests.
- This source/test evidence does not verify real Hostinger delivery, worker queue/retry behavior against a live controlled service, physical-device push, SMTP provider acceptance, production throughput, GitHub CI, release publication or a deployment. Those acceptance gates remain open; no real email was sent.
