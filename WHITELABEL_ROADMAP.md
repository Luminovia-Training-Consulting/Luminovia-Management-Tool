# White-Label Roadmap

Implementation status and remaining acceptance for Academy Self-Hosted and Academy Managed. See the [feature catalogue](FEATURES.md#editionen) for current capabilities. Acceptance applies to the authorised customer installation, its edition, signed licence and exact release revision. The [target acceptance guide](deploy/academy/TARGET-ACCEPTANCE.md) defines the procedures and required evidence.

## Implemented capabilities and remaining delivery evidence

- [x] **Time-limited support access · WL-T39.** Customer administrators can grant a verified local support account without an Academy role access to installation or course diagnostics. The purpose, duration, expiry, revocation and use are auditable. Learning content, files and messages remain protected. Verified on native PostgreSQL for both Academy editions.
- [x] **Non-interactive host preflight · WL-T31, WL-T36.** The preflight checks the signed installation plan against the OS, architecture, CPU, RAM, free storage, local Docker and Compose configuration, required tools and ports. Errors stop the check before activation. Retry behaviour and a real local port conflict were tested.
- [x] **Browser SBOM and dependency licences · WL-T40.** Both Academy browser packages include a CycloneDX inventory of shipped components and their licence texts. Package verification binds both files to the edition, Git revision and browser archive.
- [x] **API developer package · WL-T16–WL-T18, WL-T37.** The Academy API provides downloadable TypeScript and Python clients scoped to the edition and installation. Local tests cover live HTTP responses and verification of earlier signed contracts.
- [x] **Academy editions and licence boundaries.** Both dedicated editions separate course operations from the internal assignment and billing portal. Signed licences, exact release revision binding and server-side enforcement of active, grace and expired states are implemented and locally tested. [Installation guide](deploy/academy/README.md)
- [x] **Custom branding and app icons.** Academy name, logo, tab and installation icons, public links and sender identity are integrated. Installation and device acceptance remain open below. [Branding evidence](docs/WORKLOG.md#22-november-2026--academy-tab-icon-and-scoped-integration-examples)
- [x] **Signed webhooks and local delivery.** Organisation-scoped course webhooks with delivery history, retries and revocation, and the private SMTP path are implemented and tested in isolated environments. Acceptance of the customer receiver remains open below. [Webhook evidence](docs/WORKLOG.md#21-november-2026--signed-webhooks-for-both-dedicated-academies)
- [x] **Licence handoff, recovery and data export tooling.** Signed runtime handoff, licence issuance and renewal, encrypted recovery and a dedicated offboarding export are available. Operator rehearsals on the customer target remain open below. [Licence evidence](docs/WORKLOG.md#22-november-2026--academy-licence-issuance-and-roadmap-reconciliation)
- [ ] **Runtime image dependency evidence · WL-T40.** Document the SBOM and licence texts for the container image digests actually deployed.

## Acceptance for each customer installation

- [ ] **Editions, identity and privacy · WL-T01–WL-T15, WL-T27–WL-T30, WL-T34.** Verify existing internal workflows and both Academy editions against the exact release. Verify roles, direct course and lecturer assignment, organisation boundaries and licence states through the UI, HTTP/RPC, files, search, Realtime and notifications. Cover first access, username or email and password, recovery, name conflicts, credential expiry, suspension and missing permissions. Verify isolation from a second independent installation with separate keys.
- [ ] **API and data flows · WL-T16–WL-T22, WL-T37.** Map each supported business action to its API or a documented exception. Verify Swagger, schemas, actual status and error responses, concurrent and repeated calls, pagination, limits, key rotation, current permissions, exact scanned file bytes and backwards compatibility. At the customer receiver, verify webhook signatures, delivery history, retries, deduplication and revocation.
- [ ] **Branding, interface and devices · WL-T23–WL-T26, WL-T35.** Remove unnecessary Luminovia references from customer interfaces, emails, documents and API documentation. Verify names, icons, cache transitions, themes, contrast, keyboard navigation and screen-reader behaviour in German and English on supported devices. Test the installed PWA on the actual origin.
- [ ] **Activation and delivery · WL-T09, WL-T25, WL-T31, WL-T36.** Complete the verified, signed handoff from issuer to operator. Start the independent installation and confirm its exact revision, licence, domain and DNS, public TLS, redirects and Auth callbacks. Verify first administrator access, invitations and password recovery with actual inbox receipt. Test configured course notifications with opt-in and opt-out. Record channels that were disabled by agreement.
- [ ] **Operations, upgrade and recovery · WL-T29, WL-T32–WL-T36.** Connect scanner, storage, quota, backup age and migration status to target monitoring. Rehearse alarms, maintenance and incident handling. Restore an encrypted backup in isolation and execute the exact signed upgrade path while preserving accounts, roles, courses, progress, chat and protected file bytes. Document the rollback boundary, retained data and post-upgrade checks.

## Handoff and managed operations

- [ ] **Licence, approval and handoff · WL-T07, WL-T34, WL-T38–WL-T40.** Rehearse issuance, renewal and encrypted data export with the actual operator. Document the customer contract, distribution rights, third-party notices, privacy, retention, support and responsibilities. Complete and approve the [handoff templates](docs/customer-handoff/README.md) for the offer.
- [ ] **Academy Managed · WL-T29, WL-T32–WL-T33, WL-T36, WL-T38–WL-T39.** Accept operations in the independent customer environment, including provider delivery, backup scheduling and monitored upgrades. Define responsibilities, support access and incident communications. Rehearse domain handoff, migration between Self-Hosted and Managed, and offboarding with data export and verified access revocation.
- [ ] **Release decision · WL-T40.** Resolve the remaining acceptance items in the [product roadmap](ROADMAP.md) and this document. Record the revision, edition, result and evidence for each target. All required application and security checks must pass on that exact commit. Document the go/no-go decision and rollback plan before activation.
